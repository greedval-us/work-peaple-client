# Work People — desktop-клиент

Начальный каркас приложения на Electron, Vue 3 и TypeScript. Пока реализована
проверка соединения с сервером: состояние API, PostgreSQL и Redis, повтор запроса
и сообщения об ошибке. Авторизация, сотрудники и отделы появятся на следующих этапах.

## Запуск

На Windows нужны Node.js 24.14.1+ ветки 24 и npm 11+ для клиента.
API, PostgreSQL и Redis запускаются только на удалённом хосте `192.168.0.102`;
порядок подготовки описан в README репозитория `work-peaple-server`.

Перед запуском клиента откройте отдельный PowerShell и оставьте SSH-туннель работающим:

```powershell
ssh -i "$HOME/.ssh/id_ed25519_hostkey" -p 22 -N -L 127.0.0.1:50051:127.0.0.1:50051 greed@192.168.0.102
```

Учётная запись SSH — `greed`, порт по умолчанию — 22.
Параметр `-i` выбирает существующий локальный ключ `~/.ssh/id_ed25519_hostkey`.
Если сервер не принимает этот ключ, SSH запросит пароль в терминале; не сохраняйте его в файлах проекта.
Приватный ключ остаётся на вашем компьютере.
Туннель передаёт обращения к локальному порту 50051 на loopback сервера.

В другом PowerShell, из папки клиента:

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

По умолчанию клиент обращается к `127.0.0.1:50051` через этот туннель, поэтому
менять `GRPC_TARGET` не требуется. Если сервер выключен или туннель закрыт, приложение покажет
ошибку соединения; наличие сервера не требуется для сборки клиента.

## Настройки подключения

Настройки читает только main-процесс. В разработке `.env` загружается из корня
клиента; переменные процесса имеют приоритет. Упакованное приложение использует
только переменные окружения процесса и не читает `.env` рядом с установкой.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GRPC_TARGET` | `127.0.0.1:50051` | `hostname:port` или `[IPv6]:port` |
| `GRPC_TLS_ENABLED` | `false` | `true` включает проверяемое TLS-соединение |
| `GRPC_TLS_CA_PATH` | пусто | PEM-файл доверенного CA; без него используются системные корни доверия |
| `GRPC_TIMEOUT_MS` | `3000` | Срок запроса, целое число 100–30000 мс |

Основной режим подключения к `192.168.0.102` — SSH-туннель с `GRPC_TLS_ENABLED=false`:
gRPC остаётся на loopback обоих компьютеров, а SSH шифрует передачу между ними.
Для прямого подключения по сети настройте TLS на сервере или gRPC-совместимом прокси и задайте правильное
DNS-имя сертификата в `GRPC_TARGET`. Проверка сертификатов не отключается.
Путь к CA в установленном приложении удобнее задавать абсолютным.

Пример запуска установленного portable-приложения с TLS в PowerShell:

```powershell
$env:GRPC_TARGET = 'api.example.org:443'
$env:GRPC_TLS_ENABLED = 'true'
$env:GRPC_TIMEOUT_MS = '3000'
& '.\Work People-0.1.0-x64-portable.exe'
```

Не добавляйте серверные настройки и будущие токены в переменные `VITE_*`:
они становятся частью кода renderer и доступны интерфейсу.

## Структура и границы процессов

```text
src/main/            Electron, конфигурация, gRPC, проверка IPC
src/preload/         Единственный мост window.workPeople.getHealth()
src/shared/          Сериализуемый контракт результата и IPC-канал
src/renderer/src/    Vue: AppShell, ConnectionPanel, useConnection
proto/               Отслеживаемая копия protobuf-контрактов сервера
scripts/             Синхронизация контрактов
tests/               Конфигурация, доверенные адреса и реальный loopback gRPC
```

`App.vue` собирает оболочку и панель соединения; `useConnection` отвечает за
загрузку и повторную проверку. Renderer работает с `sandbox: true`,
`contextIsolation: true`, без Node.js и прямых сетевых запросов к API.
Preload собирается в один CJS-файл для sandbox и предоставляет только типизированный
`getHealth()`. Main проверяет окно, главный frame и точный адрес отправителя.
Открытие новых окон, внешняя навигация, webview и запросы разрешений запрещены.
В production CSP разрешает только локальные скрипты и стили; dev-сервер допускается
только на loopback. Ключи и пути TLS остаются в main.

Main использует нативный Node.js gRPC-клиент `@grpc/grpc-js`; grpc-web не нужен.
Успех и ошибка возвращаются через IPC как обычные объекты без экземпляров `Error`.
Каждый запрос ограничен deadline. При закрытии приложения gRPC-канал закрывается.

## Обновление контракта

Канонический контракт находится на сервере. Команда копирует все `.proto` из
дерева `../work-peaple-server/proto` в локальное дерево `proto`:

```powershell
npm run contracts:sync
npm run contracts:sync -- D:\contracts\proto
```

Проверьте diff и сохраните обновлённые `.proto` вместе с изменениями клиента.
Устаревшие версии скрипт не удаляет автоматически. Обычная сборка использует
только локальную копию и не зависит от соседнего репозитория.

## Проверки и сборка Windows

```powershell
npm run typecheck
npm test
npm run build
npm run pack
npm run dist
```

`build` создаёт `out/main/index.cjs`, `out/preload/index.cjs` и статический
renderer. `pack` создаёт распакованное приложение в `release/win-unpacked`.
`dist` создаёт NSIS-установщик и portable `.exe` x64; `dist:portable` — только
portable. Сборка установщика может загружать инструменты electron-builder.
Для публичного распространения настройте Windows code signing в среде сборки.
Без сертификата получаются неподписанные артефакты для внутренней проверки.

В пакет входят production-зависимости gRPC и `resources/proto`; `.env` и исходные
секреты не упаковываются. В dev main читает `proto` из корня проекта, в пакете —
из `process.resourcesPath`. `npm test` использует изолированный loopback gRPC для
проверки клиента; развёртывание API и баз на Windows для этих тестов не требуется.
Серверные тесты и Compose выполняются по SSH на `192.168.0.102`.
Перед выпуском проверьте запуск упакованного `.exe` и вызов health через туннель
как с работающим, так и с недоступным удалённым сервером.
